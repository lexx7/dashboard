# AGENTS.md — правила для Kimi при работе над ETL-пайплайном

> Этот файл читается агентом перед началом работы в репозитории.
> Контекст проекта: см. `spec.md` (требования), `plan.md` (архитектура),
> `tasks.md` (задачи и критерии готовности). Выполняй задачи строго в порядке
> графа зависимостей из `tasks.md`.

## Проект

ETL-пайплайн «источник → витрина»: Java 25, Spring Boot 4.x, Maven,
два PostgreSQL 17 в Docker Compose, Flyway, JUnit 5 + Testcontainers.

## Команды (запускай сам, не спрашивай)

- Инфраструктура: `docker compose up -d` (поднимает db-source:5433 и db-mart:5434)
- Наполнение источника: `psql -h localhost -p 5433 -U etl -d source -f scripts/seed_source.sql`
- Тесты: `./mvnw test` — запускать **после каждого изменения кода**, до отчёта о готовности
- Линт/формат: `./mvnw spotless:check` и `./mvnw spotless:apply`
- Perf-тест: `./mvnw test -Pperf` (только по явному запросу, долгий)

## Правила работы

1. Одна задача из `tasks.md` = одна итерация. Критерий готовности задачи —
   зелёный тест из её описания; не переходи к следующей задаче без него.
2. Перед реализацией перечитай соответствующий раздел `plan.md` — модель
   данных и контракты менять нельзя без отдельного согласования.
3. Миграции — только новые файлы `V{n}__*.sql`, никогда не редактируй
   применённые миграции. Индексы — с `CONCURRENTLY` там, где это уместно.
4. Транзакции — на уровне service/pipeline, не repository. Для db-mart —
   `martTransactionManager`.
5. Тесты: Testcontainers (singleton-контейнеры на класс, не на метод),
   именование `should_X_when_Y`, без `Thread.sleep` — только ожидания
   с таймаутом (Awaitility).
6. После каждой итерации: прогони `./mvnw test` и `./mvnw spotless:apply`,
   зафиксируй результат одной строкой в `PROCESS.md`
   (дата, задача, статус, что сломалось и как починено).

## Запрещено

- Не менять `spec.md`, `plan.md`, `tasks.md` — они фиксируют требования;
  несоответствие плана реальности — остановись и сообщи.
- Не добавлять зависимости в `pom.xml` без подтверждения.
- Не использовать `System.out.println` — только SLF4J.
- Не писать в db-source ничего, кроме seed-скрипта: источник read-only
  для пайплайна.
- Не коммитить с падающими тестами.

## Контекст, который нужен тебе всегда

- Идемпотентность и чекпоинт — ядро проекта (FR-2, FR-3): любой код,
  нарушающий «повторный запуск ничего не меняет», — дефект.
- Upsert в витрину — только с условием `WHERE products_mart.updated_at < EXCLUDED.updated_at`.
- Курсор — кортеж `(updated_at, sku)`, не одиночный timestamp.
